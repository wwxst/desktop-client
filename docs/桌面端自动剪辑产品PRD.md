# 第一部分：业务梳理

## 1. 业务背景

海外小说推文的核心生产流程，是将小说正文加工成带有配音、字幕、画面素材和推广口令的短视频，再发布到 TikTok 等内容平台，引导用户进入对应小说 APP 阅读。

对个人创作者或工作室来说，真正消耗时间的并不是单次剪出一条视频，而是同一套模板下不断重复以下操作：

1. 整理小说正文。
2. 将正文转成配音。
3. 根据配音制作字幕。
4. 准备本条视频使用的推广口令。
5. 从素材包中挑选画面素材。
6. 将音频、字幕、素材和口令放进剪映草稿。
7. 导出视频。
8. 更换下一条内容，再重复执行。

当任务量从 1 条增加到 20 条、50 条甚至更多时，人工操作会快速变成重复劳动，并产生大量漏做、错做、重复素材、命名混乱和中断后无法继续的问题。

因此，第一阶段产品的目标不是重新开发一个完整视频编辑器，而是将上述固定、重复、可规则化的步骤自动执行。

---

## 2. 业务模式

### 2.1 产品服务对象

本产品面向以下用户：

| 用户类型 | 主要特征 | 核心诉求 |
| --- | --- | --- |
| 个人创作者 | 任务量较小，剪辑经验有限 | 降低操作门槛，减少重复劳动 |
| 批量创作者 | 每天需要制作多条视频 | 提高日产量，保证流程稳定 |
| 小说推文工作室 | 多人、多项目、多素材包 | 标准化生产流程，降低培训成本 |
| 运营团队 | 需要统一模板和输出规范 | 控制成片规则、命名和任务记录 |

### 2.2 产品收费方式

第一阶段产品定位为软件工具，不绑定课程交付。

产品可以通过后端订阅体系控制使用权限，客户端负责：

- 用户登录。
- 查询当前订阅状态。
- 判断功能是否可使用。
- 处理登录失效或订阅到期。

具体套餐、售价和权益由商业侧另行制定，不在本 PRD 中写死。

### 2.3 产品业务价值

对用户：

- 减少文本拆分、配音、字幕和草稿替换的重复操作。
- 降低长篇 TTS 的云端调用成本。
- 降低素材重复和任务漏做概率。
- 批量任务中断后可以继续执行。
- 将小说推文生产流程沉淀为可复用的项目配置。

对平台方：

- 将服务从纯教学或人工协作，延伸为可持续收费的软件产品。
- 通过订阅权限、客户端版本和功能模块形成产品交付闭环。
- 为后续模板市场、模型包、素材管理和内置编辑器预留基础。

## 3. 核心业务对象

第一阶段需要先统一以下业务概念。

### 3.1 项目

“项目”代表一次可以长期保存和重复使用的小说推文生产配置。

一个项目至少包含：

- 项目名称。
- 小说 APP 名称。
- 文本内容或文本文件。
- TTS 语言、音色、语速等参数。
- 口令列表。
- 素材来源和素材使用记录。
- 剪映模板草稿位置。
- 输出目录。
- 导出命名规则。
- 批量任务及执行记录。

项目不是一条视频，也不是一个剪映草稿副本。

### 3.2 任务

“任务”代表项目中的一条待生成视频。

一条任务通常对应：

- 一段小说正文。
- 一份生成后的音频。
- 一组字幕片段。
- 一个当前口令。
- 一组本次选中的素材。
- 一个导出视频文件。

### 3.3 批次

“批次”代表用户一次点击“开始生成”后进入队列的一组任务。

批次用于记录：

- 本次准备生成多少条。
- 每条任务当前状态。
- 本次素材分配结果。
- 本次口令分配结果。
- 成功、失败、跳过数量。
- 中断恢复位置。

### 3.4 剪映模板草稿

剪映模板草稿是用户提前制作好的工作草稿，包含固定的画面结构、字幕样式、转场、贴纸或其他模板效果。

第一阶段执行规则：

- 始终使用同一个剪映工作草稿。
- 程序在该草稿中循环替换当前任务的口令、素材、配音和字幕。
- 每替换完成一条，就调用剪映导出一个视频。
- 导出完成后继续替换下一条任务。
- 不为每条视频复制一个新的剪映草稿。

### 3.5 导出视频

每条任务最终只对应一个导出结果。

默认命名规则：

```text
时间_APP名称_序号
```

示例：

```text
20260804_203015_NovelMaster_001.mp4
```

该命名规则只用于导出视频文件，不用于剪映草稿名称。

## 4. 当前人工业务流程

### 4.1 任务准备

```text
选择小说内容
→ 整理正文
→ 决定每条视频使用的文字范围
→ 准备推广口令
→ 准备视频素材包
→ 打开固定剪映模板
```

### 4.2 单条视频生产

```text
复制一段正文
→ 使用配音工具生成音频
→ 下载或保存音频
→ 导入剪映
→ 创建或导入字幕
→ 替换画面素材
→ 修改口令
→ 检查时长和画面
→ 导出
→ 手工命名
```

### 4.3 批量生产

```text
重复单条流程
→ 手工记录已使用正文
→ 手工记录已使用素材
→ 手工记录已导出序号
→ 出错后自行判断从哪里继续
```

### 4.4 产品化后的目标流程

```text
登录客户端
→ 新建或打开项目
→ 导入正文
→ 配置分段规则
→ 选择语言、音色和语速
→ 试听并生成音频
→ 导入口令和素材包
→ 绑定剪映 5.9 模板草稿
→ 预览本批次任务分配
→ 开始执行
→ 程序逐条替换同一个工作草稿并导出
→ 查看结果与失败记录
```

## 5. 业务规则

### 5.1 文本规则

1. 产品必须支持长篇正文，不能将“单次最多 500 字符”理解为整篇文章上限。
2. 如果本地 TTS 模型一次处理字符数有限，程序应自动在内部拆分，再按顺序生成和合并。
3. 文本分段应优先在自然语义边界切分，例如章节、段落、句号、问号和感叹号。
4. 分段不能把数字、英文缩写或正常句子随意截断。
5. 用户必须能在生成前看到每条任务最终使用的正文范围。

### 5.2 配音规则

1. 第一阶段默认使用用户电脑 CPU 本地生成语音。
2. 正文不依赖按字符收费的云端 TTS 才能完成。
3. 用户可以选择语言、音色和语速。
4. 用户可以先试听短文本，再生成完整任务音频。
5. 不同语言通过模型包或音色包扩展，不将产品永久限制为中文和英文。
6. 单个模型无法覆盖全部语言时，产品必须清楚展示该模型支持的语言和音色。

### 5.3 素材规则

1. 支持导入素材文件夹或压缩包。
2. 压缩包需要解压到项目缓存目录，不能直接在原压缩包中反复读取。
3. 同一批次内默认随机且不重复选取素材。
4. 素材不足时，不能静默重复；必须根据用户选择停止、提示或开启循环复用。
5. 已被成功导出任务使用的素材，需要记录使用状态。
6. 失败且未完成导出的任务，其素材是否释放，必须遵循明确规则。

建议规则：

- 任务尚未开始：素材仅预分配，可重新分配。
- 任务已写入草稿但未导出：保留分配，重试时继续使用相同素材。
- 任务成功导出：素材标记为本批次已使用。
- 用户重新生成该任务：默认沿用原素材，可手动重新抽取。

### 5.4 口令规则

1. 支持单条输入、批量粘贴和文件导入。
2. 支持顺序使用和随机使用。
3. 同一批次内默认不重复。
4. 口令数量不足时，生成前必须提示。
5. 每条任务最终使用的口令必须可在任务预览中查看和修改。

### 5.5 草稿规则

1. 第一阶段仅正式适配剪映 5.9。
2. 用户选择草稿后，程序必须检查草稿路径和关键文件是否存在。
3. 首次执行和每个批次执行前，都必须备份工作草稿。
4. 修改草稿前需要确认剪映是否正在占用相关文件。
5. 修改失败时不能留下半写入状态。
6. 回滚失败时必须立即停止整个批次，避免继续破坏草稿。

### 5.6 批量导出规则

1. 同一时间只处理一条草稿替换和导出任务。
2. 当前任务成功后，才进入下一条。
3. 当前任务失败时，按照重试策略处理。
4. 超过最大重试次数后，允许用户选择：停止批次、跳过本条或手工处理后继续。
5. 导出完成不能仅依赖固定等待时间，需要验证输出文件是否真实生成且已写入完成。
6. 已成功生成的任务不能因为后续失败而丢失完成记录。

# 第二部分：痛点与卡点分析

## 6. 用户痛点

### 6.1 长文本不能直接进入生产流程

#### 现状

小说正文通常远超过几百字。很多 TTS 演示页或接口以 300～500 字作为一次输入限制，用户必须手工拆分、多次生成、再合并音频。

#### 造成的问题

- 拆分耗时。
- 容易漏句、重复句或顺序错误。
- 分段位置不自然，语音停顿异常。
- 音频合并后难以对应字幕。

#### 产品解决方向

产品接受整篇长文本，在内部完成文本清洗、自然分段、逐段 TTS、音频拼接和字幕时间轴整合。

---

### 6.2 云端 TTS 成本和可用性不稳定

#### 现状

长篇小说配音字符数高，云端 TTS 按量收费；接口额度、账号、网络和平台政策也可能影响生产。

#### 造成的问题

- 任务量越大，成本越高。
- 网络不稳定时无法生成。
- 第三方接口变化会导致产品核心功能不可用。
- 小说正文上传第三方服务存在内容和隐私顾虑。

#### 产品解决方向

第一阶段使用成熟开源本地 TTS 方案，依靠用户电脑 CPU 生成语音；产品提供模型管理和多语言扩展能力。

---

### 6.3 音色和语言覆盖不足

#### 现状

只放少量中文、英文音色无法覆盖海外小说推文的实际市场，也容易让用户误以为产品永久只支持两种语言。

#### 造成的问题

- 不同市场无法使用。
- 同类视频音色重复，内容同质化。
- 模型体积过大时，全部内置又会增加安装包和下载压力。

#### 产品解决方向

采用“客户端核心程序 + 可安装模型包”的结构。首发提供经过验证的基础语言和音色，后续通过模型中心增加语言；界面按模型真实能力展示可用选项。

---

### 6.4 批量替换操作高度重复

#### 现状

每条视频都要重复导入音频、替换字幕、替换素材、修改口令和导出。

#### 造成的问题

- 人工日产量受限。
- 工作时间主要消耗在重复点击。
- 操作人员培训成本高。
- 长时间重复操作容易错位和漏改。

#### 产品解决方向

将每条视频拆成结构化任务，由程序按队列逐条修改同一个剪映工作草稿并导出。

---

### 6.5 素材随机容易重复

#### 现状

人工从大量素材中挑选，很难准确记住哪些素材已经使用。

#### 造成的问题

- 同一批视频中画面重复。
- 人工记录素材使用状态成本高。
- 中途退出后无法恢复随机顺序。

#### 产品解决方向

导入时建立素材索引，批次开始前预分配素材，并将随机种子、任务分配和使用状态写入项目数据。

---

### 6.6 口令与任务容易错配

#### 现状

推广口令通常由用户从表格、聊天记录或后台复制，人工替换时容易遗漏或重复。

#### 造成的问题

- 视频内容和口令对应错误。
- 口令重复使用。
- 导出后才发现错误，需要重新制作。

#### 产品解决方向

在执行前生成任务预览表，明确显示“正文、音频、口令、素材、序号”的最终对应关系，并在开始后锁定本批次分配。

---

### 6.7 剪映草稿格式存在版本兼容风险

#### 现状

剪映不同版本的草稿结构可能变化，草稿文件也可能在剪映运行时被占用。

#### 造成的问题

- 写入后剪映无法打开草稿。
- 字段错误导致时间线异常。
- 程序适配范围过大，开发和测试不可控。

#### 产品解决方向

第一阶段锁定剪映 5.9，建立模板校验、版本识别、执行前备份、原子写入和失败回滚机制。

---

### 6.8 自动导出容易受界面状态影响

#### 现状

若导出依赖桌面自动化，窗口焦点、弹窗、渲染时间、电脑性能和剪映状态都会影响稳定性。

#### 造成的问题

- 点击位置失效。
- 导出还未完成就进入下一条。
- 文件名输入失败。
- 异常弹窗阻塞整个队列。

#### 产品解决方向

将“草稿写入”和“剪映导出控制”拆为两个阶段；导出执行需要状态检测、超时、重试、输出文件验证和人工接管入口。

---

### 6.9 中断后无法准确恢复

#### 现状

人工批量制作中，软件退出、电脑重启、剪映崩溃或单条任务失败后，用户需要自己判断已经做到哪条。

#### 造成的问题

- 重复导出。
- 跳过任务。
- 素材和口令重新随机，前后不一致。
- 已完成结果无法与原任务对应。

#### 产品解决方向

为批次和任务设计持久化状态机，每个关键步骤执行后写入检查点。重新打开项目时，系统显示可恢复批次及建议恢复位置。

---

### 6.10 当前代码与目标产品之间存在缺口

当前仓库已经具备 Electron、React、登录、订阅查询、工作台和智剪界面原型，但尚未形成小说推文生产闭环。

主要缺口包括：

- 小说项目还只是导航入口，没有完整业务页面。
- renderer 还没有安全的本地文件读写业务 IPC。
- 没有项目持久化结构。
- 没有长文本处理、TTS、字幕和音频流水线。
- 没有素材索引、解压和随机分配。
- 没有剪映草稿适配层。
- 没有批量任务状态机和恢复能力。
- 当前智剪原型容易让开发方向偏向完整编辑器，而不是先完成业务闭环。

因此，第一阶段必须先建立小说推文业务模块，不能继续把主要开发资源投入自研多轨编辑器。

---

## 7. 核心开发卡点

### 7.1 本地 TTS 引擎集成

需要解决：

- Electron 如何调用本地原生可执行程序或 Node 原生模块。
- Windows x64 运行环境和依赖打包。
- 不同模型的输入格式、采样率和音色参数统一。
- 长文本分段与音频拼接。
- 模型下载、校验、安装、删除和升级。
- CPU 性能差异和任务进度反馈。

### 7.2 字幕时间轴生成

需要解决：

- 文本分段与音频片段一一对应。
- 每段真实音频时长读取。
- 合并后时间偏移累计。
- 字幕过长时的二次断句。
- 剪映草稿字幕结构映射。

### 7.3 剪映 5.9 草稿适配

需要解决：

- 模板草稿中的素材、音频、文本轨道如何识别。
- 哪些轨道是固定模板，哪些占位资源允许替换。
- 路径、时长、片段 ID 和素材 ID 的一致性。
- 草稿备份、写入和回滚。
- 剪映打开草稿后的刷新方式。

### 7.4 剪映自动导出

需要解决：

- 启动或唤起剪映。
- 确保正确草稿已加载。
- 等待素材和字幕完成加载。
- 打开导出、设置文件名和路径。
- 判断导出进度和成功状态。
- 处理升级提示、恢复弹窗、素材丢失和导出失败弹窗。

### 7.5 任务幂等与恢复

需要解决：

- 同一任务重复执行时不能生成不可控的重复结果。
- 成功导出的任务不能因程序重启变回待处理。
- 重试时口令和素材不能自动变化。
- 草稿写入完成但导出状态未知时，需要进入“待确认”状态，而不是直接重跑。

### 7.6 文件和路径兼容

需要解决：

- 中文路径、空格路径和超长路径。
- 文件名非法字符。
- U 盘、移动硬盘和网络盘断开。
- 磁盘剩余空间不足。
- 防病毒软件或 Windows 权限阻止写入。

# 第三部分：产品目标与范围

## 8. 产品定位

### 8.1 一句话定位

一款面向海外小说推文创作者的 Windows 批量生产工具，通过本地 TTS、素材编排和剪映 5.9 草稿自动替换，将长篇小说正文批量生成可发布视频。

### 8.2 第一阶段产品目标

第一阶段必须跑通以下完整闭环：

```text
导入长篇正文
→ 自动拆分任务
→ 本地生成配音
→ 生成字幕
→ 分配口令和素材
→ 修改同一个剪映 5.9 工作草稿
→ 调用剪映逐条导出
→ 保存结果和任务记录
```

### 8.3 第一阶段成功标准

产品不是“页面做出来”就算完成，而是满足：

1. 用户能独立创建项目并完成配置。
2. 用户能导入一篇长文本并生成多条任务。
3. 用户无需手工逐段调用 TTS。
4. 用户能在批量执行前检查每条任务的口令和素材分配。
5. 程序能复用同一个工作草稿连续生成多条视频。
6. 任意一条失败不会丢失已完成结果。
7. 软件重启后可以识别未完成批次并继续。
8. 导出文件按照统一规则命名且与任务一一对应。

### 8.4 第一阶段不做

- 不开发完整多轨剪辑器。
- 不替代剪映的复杂编辑功能。
- 不支持用户自由搭建任意剪辑工作流。
- 不在第一阶段支持多个剪映大版本。
- 不做移动端。
- 不把大模型脚本生成作为必经步骤。
- 不做对标账号抓取、洗稿和 Agent 自动决策。
- 不做团队协作、云素材库和云端任务渲染。

### 8.5 后续版本方向

下一个大版本再评估：

- 基于 OpenVideo 方向的内置编辑器。
- 模板编辑器。
- 多轨时间线。
- 素材语义理解与镜头匹配。
- AI Agent 和可配置工作流。
- 云端项目同步与团队协作。

## 14. 正文导入与文本处理

### 14.1 目标

支持用户直接导入长篇小说正文，并自动拆解为可执行任务。

### 14.2 输入方式

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| TEXT-001 | 文本框粘贴正文 | P0 |
| TEXT-002 | 导入 TXT 文件 | P0 |
| TEXT-003 | 支持 UTF-8、常见中文编码识别 | P0 |
| TEXT-004 | 导入多个 TXT 文件并按顺序合并 | P1 |
| TEXT-005 | 支持 DOCX 等格式 | P2 |

### 14.3 文本清洗

用户可以选择执行：

- 删除多余空行。
- 合并连续空格。
- 统一换行符。
- 去除首尾空白。
- 删除指定前缀或广告尾巴。
- 将特殊引号或符号标准化。

清洗后必须保留“查看原文”和“撤销清洗”的能力，不能直接覆盖用户原始文件。

### 14.4 任务拆分方式

第一阶段至少支持：

1. **按章节拆分**：识别“第 X 章”等章节标题。
2. **按目标字数拆分**：例如每条 800～1500 字。
3. **按目标配音时长拆分**：通过字数和语速预估，生成后以实际时长校正。
4. **手工拆分**：用户在预览中插入或删除分割点。

### 14.5 内部 TTS 分片

“任务拆分”和“TTS 分片”必须区分：

- 任务拆分决定最终生成几条视频。
- TTS 分片只是为了让单条长正文适配模型输入限制。
- 一条任务可以由多个 TTS 分片组成，最终合并成一个音频文件。

例如：

```text
任务正文 1200 字
→ 内部分为 300 + 280 + 320 + 300 字
→ 生成 4 个临时音频
→ 合并为该任务的 1 个完整音频
```

### 14.6 任务预览字段

- 任务序号。
- 正文开头摘要。
- 字数。
- 预计时长。
- 拆分位置。
- 状态。

用户可执行：

- 编辑正文。
- 合并相邻任务。
- 拆分当前任务。
- 调整顺序。
- 删除任务。

### 14.7 验收标准

- 导入 1 万字以上文本时界面不能卡死。
- 用户能在生成前确认任务数量和正文范围。
- 不因 TTS 单次字符限制要求用户手工拆整篇文章。
- 文本处理结果关闭软件后仍能恢复。

## 15. 本地 TTS 配音

### 15.1 目标

通过用户电脑 CPU 将正文生成语音，支持试听、批量生成和保存音频。

### 15.2 基础功能

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| TTS-001 | 选择语言 | P0 |
| TTS-002 | 选择音色 | P0 |
| TTS-003 | 调整语速 | P0 |
| TTS-004 | 输入短文本试听 | P0 |
| TTS-005 | 为单条任务生成音频 | P0 |
| TTS-006 | 为整个批次生成音频 | P0 |
| TTS-007 | 保存音频到项目目录 | P0 |
| TTS-008 | 显示生成进度和当前分片 | P0 |
| TTS-009 | 暂停或取消未完成的批量生成 | P1 |
| TTS-010 | 音量、音调等高级参数 | P2 |

### 15.3 语言与音色展示规则

- 语言列表来自已安装模型，不写死为中文和英文。
- 选择语言后，只展示该模型真实支持的音色。
- 音色显示友好名称，同时保留内部模型 ID。
- 模型未安装时，展示“需要安装”，不能展示为可直接使用。
- 默认音色需要经过产品侧实际试听后确定。

### 15.4 模型中心

模型中心至少包含：

- 模型名称。
- 支持语言。
- 支持音色数量。
- 模型大小。
- 预计磁盘占用。
- 安装状态。
- 版本。
- 下载、暂停、继续、删除。
- 文件完整性校验。

### 15.5 TTS 生成流程

```text
读取任务正文
→ 文本标准化
→ 根据模型限制进行内部切分
→ 逐分片生成音频
→ 读取每段实际时长
→ 合并音频
→ 生成任务级音频信息
→ 更新字幕时间轴
→ 标记完成
```

### 15.6 音频输出

每条任务至少保存：

- 最终音频文件。
- 总时长。
- 采样率。
- 使用的语言、模型、音色和语速。
- 分片列表及每片时长。
- 生成时间。
- 文本内容哈希。

当正文或 TTS 参数变化时，原音频标记为“已过期”，不能继续当成最新结果使用。

### 15.7 错误处理

| 异常 | 产品行为 |
| --- | --- |
| 模型未安装 | 阻止生成并引导安装 |
| 模型文件损坏 | 提示重新校验或重新下载 |
| 单个分片生成失败 | 自动重试，超过次数后标记任务失败 |
| 磁盘空间不足 | 立即停止并保留已完成分片 |
| 用户取消 | 当前安全点停止，保留已完成结果 |
| 程序重启 | 能识别未完成的 TTS 任务并继续或重新开始 |

### 15.8 验收标准

- 完成语言、音色和语速选择。
- 试听和正式生成使用同一套引擎参数。
- 可对超过模型单次输入限制的正文自动分片。
- 生成后的完整音频顺序正确，无明显截断。
- 音频文件可以独立播放和保存。
- 批量生成时界面保持可响应。

## 16. 字幕生成

### 16.1 目标

根据正文分片和音频真实时长生成可写入剪映草稿的字幕片段。

### 16.2 功能需求

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| SUB-001 | 根据 TTS 分片生成基础字幕时间轴 | P0 |
| SUB-002 | 根据标点进行字幕二次断句 | P0 |
| SUB-003 | 展示字幕文本、开始时间和结束时间 | P0 |
| SUB-004 | 支持手工修改字幕文本 | P1 |
| SUB-005 | 支持导出 SRT | P1 |
| SUB-006 | 复杂逐字高亮 | P2 |

### 16.3 字幕规则

- 字幕文本不能超过产品配置的单行或单片段长度。
- 断句优先使用标点，不随意切断词语和数字。
- 开始时间和结束时间必须连续且不能出现负数。
- 最后一条字幕结束时间不能明显超过音频总时长。
- 第一阶段字幕样式主要沿用剪映模板，占位字幕只负责替换文本和时间。

### 16.4 过期规则

以下任一变化后，字幕标记为需要重新生成：

- 正文变化。
- TTS 音色变化。
- 语速变化。
- 音频重新生成。
- 字幕断句规则变化。

- 批量粘贴，一行一个。
- TXT 或 CSV 导入。

### 18.1 导入方式

## 19. 剪映模板绑定与校验

### 19.1 目标

### 19.2 绑定流程


- 小说配音轨道。

- 一个或多个素材占位轨道。

程序不能依赖“第 1 条轨道一定是什么”的脆弱规则，应该通过模板标记、固定命名或可确认的轨道 ID 建立映射。

- 草稿目录存在。
- 关键草稿文件存在。

- 占位资源数量满足模板规则。

- 剪映当前未锁定草稿文件，或用户已关闭草稿。

### 19.5 备份规则

- 首次绑定时创建原始模板备份。
- 每次批次开始前创建批次备份。
- 每次写入使用临时文件，完成校验后再替换正式文件。
- 只保留最近若干备份时，需要在设置中可配置。
- 用户可手工恢复原始模板。

## 20. 批次创建与任务预览

## 21. 批量执行引擎

### 21.1 总体流程

```text
创建批次快照
→ 备份剪映工作草稿
→ 锁定任务、口令和素材分配
→ 处理任务 1
   → 校验输入
   → 生成任务草稿数据
   → 原子写入工作草稿
   → 启动或切换到剪映
   → 打开工作草稿
   → 执行导出
   → 校验输出文件
   → 记录成功
→ 处理任务 2
→ ……
→ 完成批次
```

### 21.2 执行控制

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| RUN-001 | 开始批次 | P0 |
| RUN-002 | 显示当前任务和总体进度 | P0 |
| RUN-003 | 安全暂停 | P0 |
| RUN-004 | 恢复批次 | P0 |
| RUN-005 | 取消未完成任务 | P0 |
| RUN-006 | 自动重试单条失败任务 | P0 |
| RUN-007 | 跳过失败任务继续执行 | P1 |
| RUN-008 | 仅重新执行指定失败任务 | P1 |

### 21.3 暂停定义

暂停不是立即杀死当前进程。

安全暂停规则：

- 若还未修改草稿，可立即暂停。
- 若正在写入草稿，完成原子写入或回滚后暂停。
- 若剪映正在导出，等待当前导出成功、失败或超时后暂停。
- 暂停后不进入下一条任务。

### 21.4 取消定义

- 已成功任务保留。
- 当前正在导出的任务进入待确认或失败状态。
- 未开始任务标记为已取消。
- 取消后保留批次记录，不直接删除。

### 21.5 任务状态机

```text
DRAFT          草稿任务，尚未准备
READY          所有前置资源已准备
QUEUED         已进入批次队列
PREPARING      正在校验和准备草稿数据
WRITING_DRAFT  正在写入剪映草稿
DRAFT_READY    草稿写入并校验完成
EXPORTING      剪映正在导出
VERIFYING      正在验证输出文件
SUCCEEDED      已成功
FAILED         已失败
WAIT_CONFIRM   状态不确定，需要用户确认
PAUSED         因批次暂停而等待
CANCELLED      已取消
SKIPPED        已跳过
```

### 21.6 状态持久化

以下节点必须立即保存：

- 任务进入队列。
- 素材和口令分配锁定。
- 开始写草稿。
- 草稿写入成功。
- 开始导出。
- 发现输出文件。
- 输出文件验证成功。
- 任务失败或等待确认。
- 批次暂停、取消或完成。

## 22. 剪映导出控制

### 22.1 目标

让客户端能够在用户电脑上控制剪映完成逐条视频导出，并可靠判断结果。

### 22.2 导出前置条件

- 剪映路径已配置。
- 目标版本为已适配的剪映 5.9。
- 工作草稿写入完成。
- 剪映没有停留在会阻塞导出的异常弹窗。
- 输出目录可写。

### 22.3 导出过程

产品需要展示当前所处阶段，而不是只显示一个总进度条：

```text
正在启动剪映
正在打开工作草稿
正在等待草稿加载
正在打开导出页面
正在设置文件名
正在导出
正在验证文件
```

### 22.4 输出文件验证

判定成功至少需要：

- 目标文件已出现。
- 文件大小大于合理最小值。
- 文件大小在连续检测中保持稳定，说明写入结束。
- 文件可以读取基础媒体信息。
- 视频时长与任务预期时长在允许误差范围内。

### 22.5 超时与异常

| 异常 | 默认处理 |
| --- | --- |
| 剪映未启动 | 自动重试启动 |
| 草稿未加载 | 重试打开，超过次数后失败 |
| 出现未知弹窗 | 暂停并请求用户处理 |
| 导出超时 | 进入待确认，不直接重复导出 |
| 输出文件已存在 | 使用预设冲突策略 |
| 输出文件损坏 | 标记失败并允许重试 |
| 剪映崩溃 | 保存状态，重启剪映后重试 |

### 22.6 文件名冲突策略

提供：

- 阻止并提示。
- 自动追加序号。
- 覆盖原文件。

默认使用“自动追加序号”，禁止静默覆盖。

## 29. 数据持久化原则

1. 项目配置和任务状态必须落盘，不能只保存在 React 内存中。
2. 大文件不直接写入项目 JSON，只保存路径和元数据。
3. 写入关键状态时使用临时文件加原子替换，减少文件损坏。
4. 项目升级需要带 schemaVersion，并提供迁移逻辑。
5. 日志和项目业务数据分开保存。
6. 用户删除项目时，需要明确“只删除项目记录”还是“连同缓存和生成文件一起删除”。

# 第六部分：非功能需求

## 30. 性能

- 导入 1 万字以上文本时，页面保持可交互。
- 大文件扫描、哈希、解压和 TTS 均不得阻塞 renderer 主线程。
- 项目列表首次打开目标响应时间不超过 2 秒；大项目允许先展示骨架和渐进加载。
- 批量任务运行时，用户仍能查看日志和进度。
- CPU 使用率可以较高，但必须允许用户选择性能档位。

---

## 31. 稳定性

- 任一单条任务失败不能破坏整个项目数据。
- 草稿写入失败必须回滚或停止。
- 软件异常退出后必须能识别未完成任务。
- 已成功导出的文件和状态不能因后续异常丢失。
- 关键文件写入需要备份和校验。

---

## 32. 安全

- renderer 不直接获得 Node、文件系统或完整 IPC 权限。
- 所有系统操作通过明确的 preload API 暴露。
- 所有文件路径和 IPC 参数需校验。
- 登录 Token 不暴露给 renderer，也不写入普通日志。
- 模型包和更新包需要校验来源及完整性。
- 解压文件时防止路径穿越。
- 诊断包默认脱敏账号、Token、正文和本地绝对路径。

---

## 33. 兼容性

第一阶段正式支持范围建议：

- Windows 10/11 64 位。
- Electron 客户端对应的 x64 安装包。
- 剪映 5.9 指定小版本范围。
- 常见中文和英文 Windows 用户目录。
- 本地磁盘优先，不承诺网络盘稳定执行。

其他系统或剪映版本可以提示“未验证”，不能默认为兼容。

## 34. 可观测性

每个批次日志至少记录：

- 客户端版本。
- 操作系统版本。
- 剪映版本。
- 项目和批次 ID。
- 任务 ID。
- 当前执行阶段。
- 阶段开始和结束时间。
- 重试次数。
- 错误码和错误摘要。
- 输出文件验证结果。

日志不得默认记录完整小说正文和账号密码。

# 第九部分：测试与验收

## 40. P0 主流程验收用例

### 40.1 长文本生成

准备一份超过 1 万字的 TXT：

- 可以正常导入。
- 能拆成多条任务。
- 每条正文范围可预览。
- TTS 内部分片对用户透明。
- 所有任务能生成完整音频和字幕。

### 40.2 多语言和音色

- 已安装模型对应的语言和音色能正确展示。
- 未安装模型不能直接选择。
- 切换音色和语速后试听结果变化。
- 修改参数后旧音频显示为已过期。

### 40.3 素材随机不重复

准备数量充足的素材：

- 创建 10 条任务。
- 任务预览中分配结果不重复。
- 暂停和重启软件后分配不变化。
- 重新抽取指定任务时只影响指定任务。

### 40.4 同一草稿连续导出

使用一个剪映 5.9 工作草稿连续执行至少 10 条任务：

- 不生成 10 个草稿副本。
- 每条任务的正文音频、字幕、口令和素材正确。
- 每条只生成一个目标视频。
- 输出命名符合规则。
- 成功记录与文件一一对应。

### 40.5 中断恢复

批次执行到中间时强制关闭客户端：

- 重启后能识别未完成批次。
- 已成功任务不重复执行。
- 未完成任务保留原口令和素材分配。
- 状态不确定的任务进入待确认。
- 用户可以继续剩余任务。

### 40.6 草稿保护

模拟草稿写入失败：

- 程序停止当前任务。
- 原始草稿可以恢复。
- 不继续处理后续任务。
- 日志中有明确错误和恢复结果。

## 41. 第一阶段发布验收标准

只有同时满足以下条件，第一阶段才算具备发布条件：

### 41.1 业务闭环

- 可从长文本开始，最终连续导出多条视频。
- 不需要用户手工逐条替换音频、字幕、口令和素材。
- 同一剪映工作草稿可循环使用。

### 41.2 稳定性

- 10 条标准测试任务可连续完成。
- 单条失败不丢失已完成结果。
- 任务支持暂停、恢复和失败重试。
- 草稿有备份和回滚。

### 41.3 可用性

- 新用户能够按照页面顺序完成配置。
- 所有阻塞条件在开始前明确提示。
- 错误信息能说明发生在哪个阶段以及下一步怎么处理。

### 41.4 数据完整性

- 项目、任务、素材、口令和结果对应关系可恢复。
- 导出文件可追溯到具体项目、批次和任务。
- 项目关闭和客户端重启后数据不丢失。

### 41.5 安全边界

- renderer 不直接访问 Node 和任意系统能力。
- Token 不暴露给 renderer。
- 模型包、压缩包和本地路径经过校验。

# 第十部分：风险与待决策项

## 42. 主要风险

| 风险 | 影响 | 应对方式 |
| --- | --- | --- |
| 剪映草稿结构变化 | 草稿无法写入或打开 | 第一阶段锁定 5.9，建立版本白名单 |
| 剪映自动化受 UI 影响 | 导出不稳定 | 状态检测、超时、重试和人工接管 |
| 本地 CPU 性能差异大 | 生成速度不一致 | 性能档位、进度显示、基准测试 |
| 多语言模型体积大 | 安装包过大 | 模型按需下载，不全部内置 |
| 素材包格式混乱 | 扫描和匹配失败 | 导入校验、错误文件清单、分类预览 |
| 长路径和权限问题 | 文件读写失败 | 路径检查、写入测试、友好错误提示 |
| 状态机不完整 | 重复导出或漏任务 | 每个关键阶段持久化、幂等设计 |
| 功能范围不断扩张 | 第一版无法按时闭环 | 严格执行第一阶段不做清单 |

# 附录 B：产品开发原则

1. 先梳理业务，再设计页面。
2. 每个功能必须对应真实业务痛点。
3. 先验证最难技术链路，再扩展页面数量。
4. 项目和任务状态必须持久化。
5. 批量执行必须可恢复。
6. 草稿操作必须可回滚。
7. 不为每条视频复制剪映草稿。
8. 导出视频命名不等于草稿命名。
9. 不把 TTS 单次分片限制变成整篇正文限制。
10. 第一阶段不自研完整多轨编辑器。
11. UI 美化不能优先于业务闭环稳定。
12. 未通过真实连续导出测试的功能，不视为完成。
