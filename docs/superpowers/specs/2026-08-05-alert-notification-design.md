# 右下角 Alert 通知组件设计

## 背景

TTS 配音页和插件中心目前分别维护 `tts-notice` 与 `plugins-notice`，组件结构和状态配色重复，提示还会占用页面布局空间。项目需要一个自有、可复用的通知组件，同时统一现有两处提示。

视觉参考来自 TDesign Vue Next 的 Alert 组件：保留状态图标、标题、说明和关闭操作的内容层级，但不安装、不导入 TDesign 组件库或图标库。最终交互按已确认的 VS Code 风格调整为窗口右下角的非阻塞通知，而不是页面内联 Alert 或模态弹窗。

## 目标

- 在 `src/renderer/src/components/ui` 中新增可复用的 `AlertNotification`。
- 支持 `info`、`success`、`warning`、`error` 四种状态。
- 同时迁移 TTS 配音页和插件中心的现有结果提示。
- 移除两处页面各自维护的通知结构与重复样式。
- 保留现有业务调用、任务进度、下载进度和媒体播放行为。

## 非目标

- 不引入 TDesign、TDesign Icons 或其他通知组件依赖。
- 不新增全局 Provider、命令式通知 API、通知中心或历史记录。
- 不实现多条通知并发堆叠；同一页面的新提示替换当前提示。
- 不把表单字段错误或登录页顶部 Toast 迁入本次范围。
- 不修改 TTS、插件安装、插件卸载和目录打开的主进程接口。

## 组件结构

新增以下自有 UI 组件文件：

- `src/renderer/src/components/ui/AlertNotification.tsx`
- `src/renderer/src/components/ui/AlertNotification.css`

组件采用受控接口，页面继续负责业务提示状态：

```ts
type AlertNotificationVariant = 'info' | 'success' | 'warning' | 'error'

interface AlertNotificationProps {
  open: boolean
  variant: AlertNotificationVariant
  title?: string
  message: ReactNode
  confirmLabel?: string
  onClose: () => void
}
```

默认标题映射如下：

- `info`：提示
- `success`：操作成功
- `warning`：请注意
- `error`：操作失败

组件通过 React Portal 渲染到 `document.body`，避免受到页面容器的 `overflow`、网格布局或层叠上下文影响。状态图标使用项目现有的 Lucide React；右上角关闭操作使用 `X` 图标，底部确认操作复用自有 `Button`。

## 视觉规范

- 通知固定在应用窗口右下角，与窗口右边和底边保持稳定间距。
- 默认宽度约 `360px`，窄窗口下使用可用宽度并保留两侧安全间距。
- 通知背景为纯白色，使用浅灰边框，外框 `border-radius` 为 `0`。
- 使用轻量阴影建立浮层层级，不添加遮罩或背景模糊。
- 左侧状态图标保留蓝、绿、黄、红四种语义色；白色通知背景不随状态改变。
- 标题使用主要文字色和较高字重，说明使用次要文字色并允许自然换行。
- 关闭按钮位于右上角，“知道了”按钮位于内容底部右侧。
- 出现时使用短促的淡入与轻微位移动画，关闭时立即移除；减少动态效果偏好下禁用出现动画。

## 交互与可访问性

- 通知为非模态浮层，不锁定页面焦点、不锁定滚动，页面在通知显示期间仍可操作。
- 通知不会自动消失。用户可通过右上角关闭按钮或“知道了”按钮移除通知。
- 通知出现时不主动抢夺当前焦点；关闭后也不需要恢复焦点。
- `error` 和 `warning` 使用 `role="alert"` 与 assertive 实时播报。
- `success` 和 `info` 使用 `role="status"` 与 polite 实时播报。
- 图标只承担视觉语义并对辅助技术隐藏；关闭按钮提供明确的可访问名称。
- 同一页面出现新提示时直接更新当前通知，不叠加多个通知。

## TTS 配音页迁移

移除页面顶部的 `tts-notice` 结构及对应状态样式，继续使用现有 `notice` 业务状态驱动 `AlertNotification`。

不再创建以下中间过程通知：

- 生成音色试听时的“正在生成试听”。

过程状态继续由现有卡片按钮加载态、任务进度和生成状态承担。以下结果继续显示通知：

- 语音资源目录读取失败。
- 未安装插件或未选择音色。
- 试听生成或播放失败。
- 正式配音任务完成、失败或取消。
- 正式配音任务创建失败。
- 取消任务的返回结果。
- WAV 保存成功或失败。

试听成功仍然不显示通知。

## 插件中心迁移

移除 `PluginsView` 中两处重复的 `plugins-notice` 结构及对应状态样式，使用同一个 `AlertNotification`。

安装开始时不再显示“正在下载插件，请保持网络连接”。下载过程继续由现有按钮状态和下载进度承担。以下结果继续显示通知：

- 插件安装成功或失败。
- 插件卸载成功或失败。
- 插件目录打开失败。

插件详情页和插件列表页共享当前 `notice` 状态，因此切换视图时仍然只显示一条通知。

## 状态与数据流

页面异步操作完成后更新本地 `notice` 状态。`AlertNotification` 只接收展示数据，不读取业务 API，也不维护业务结果队列。

关闭按钮和“知道了”调用同一个 `onClose`，由页面将 `notice` 设为 `null`。后续结果到达时可替换当前提示，避免旧结果阻挡新的错误信息。

组件卸载时 Portal 内容随 React 树移除，不注册持续存在的全局事件。

## 测试范围

新增组件级测试，覆盖：

- 四种状态均可渲染对应默认标题、状态类和图标。
- 自定义标题、正文和确认按钮文字正确渲染。
- 右上角关闭按钮与“知道了”都会触发 `onClose`。
- `open=false` 时不渲染通知。
- 错误/警告与成功/信息使用正确的实时播报语义。
- CSS 契约包含固定右下角定位、白色背景和直角外框。

更新 TTS 配音页测试，覆盖：

- 试听生成期间不显示中间过程通知。
- 试听成功不显示通知，试听失败显示错误通知。
- 正式生成、取消和保存的结果继续显示对应通知。
- 关闭通知不会改变现有任务、音色选择或试听状态。

更新插件中心测试，覆盖：

- 安装开始后不显示中间过程通知。
- 安装、卸载和目录打开结果显示共享通知组件。
- 列表页和详情页均不再渲染旧的 `plugins-notice`。

最终验证执行完整测试、类型检查、lint、生产构建和 `git diff --check`。
