# 编辑器项目持久化边界

> 状态：计划中，尚未实现
> 适用范围：Editor V2 项目/草稿数据与全局素材库的未来映射

## 目标

为编辑器建立类似剪映“项目/草稿”的可恢复模型：项目可以保存、重新打开，并在素材源文件失效后通过全局素材库身份重新定位。这里借鉴的是项目生命周期和数据归属，不复制剪映工程格式、缓存目录或导出系统。

## 计划中的文件位置

项目文件计划保存到 Main 管理的：

```text
userData/projects/<projectId>/project.json
```

Renderer 不直接读写该目录；未来通过明确的 Main/Preload 业务 IPC 保存和加载项目。

## 数据归属

项目文件计划保存：

- `projectId`、项目名称和更新时间
- 画布比例
- 项目素材引用
- 轨道和时间线片段
- 编辑器草稿表格及必要的版本信息

全局素材引用保存稳定的 `libraryAssetId`。项目临时导入且未加入全局库的素材保存 `projectAssetId` 与 `sourcePath`，不复制源文件，也不自动加入全局库。

项目文件不保存运行时 `blob:` URL、加载/错误状态、选中状态、播放位置、Undo/Redo 历史或面板尺寸。打开项目时由 Renderer 重新建立这些运行时状态，并由 Main 检查来源文件是否可用。

## 失效素材与引用次数

文件丢失时，项目引用保持不变并标记为失效；重新定位只更新对应来源路径或全局素材元数据，不改变原素材 ID。项目持久化完成后，才能通过 `projectAssetId -> libraryAssetId` 映射可靠统计项目引用次数。

因此，在项目持久化和稳定素材映射实现前，不实现“使用次数”字段或排序，避免把当前工作区临时状态误当成跨项目事实。

## 托管缓存边界

当前全局素材库只保存用户源文件路径和元数据，没有应用托管的缓存对象。未来的“未引用缓存清理”只能作用于应用登记在托管根目录内、没有持久项目引用且不再被任务使用的缓存；不得删除用户的 `sourcePath`。在托管缓存模型出现前，不提供清理按钮。

## 实现前置条件

以下能力属于后续实现，不代表当前已完成：

1. Main 侧项目目录、版本化读写和原子保存。
2. Preload 的项目新建、保存、加载和列出业务 IPC。
3. Editor V2 草稿状态到持久化 DTO 的序列化/反序列化。
4. 全局素材 ID 与项目素材 ID 的稳定映射及迁移策略。
5. 托管缓存登记、引用 lease 和清理策略。
