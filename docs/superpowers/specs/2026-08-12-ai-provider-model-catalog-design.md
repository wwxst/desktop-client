# AI 厂商与模型目录设计

> 状态：待实现设计
> 范围：AI 模型设置页、模型目录 IPC、Main 配置边界

## 目标

将现有单一设置表单改为模型管理页面。用户可以通过“模型服务商”模式选择后台目录中的厂商和模型，也可以通过“自定义配置”模式添加兼容接口与自定义模型 ID。

## 设置页交互

主页面以单一表格直接展示模型数据行，不增加“已添加”等分组标题，并只提供添加、编辑和删除操作。模型不提供启用/停用状态，也不提供默认模型；所有已添加模型都是可选择的配置。具体 AI 任务必须显式指定要使用的模型配置，设置页不隐式选择第一个或最后添加的模型。点击“添加模型”打开双模式弹窗。

“模型服务商”模式按以下顺序展示：

1. 大模型厂商
2. 模型
3. API Key

厂商和模型使用下拉选择控件。选择厂商后，模型下拉只显示该厂商目录中的模型并默认选中推荐模型。厂商官方 Base URL 由应用内部使用，不在服务商模式中展示，也不允许用户修改。

“自定义配置”模式按以下顺序展示：

1. Base URL
2. 模型 ID
3. API Key

自定义配置不依赖后台厂商和模型目录。第一版内部固定使用 OpenAI Chat Completions 兼容协议，不向用户展示 API 格式选项。用户手动填写 Base URL 和模型 ID，可用于代理网关、企业私有部署和目录外兼容服务。

API Key 继续使用密码输入框，不从 Main 状态回填，保存成功后清空。服务商模式保存目录中的稳定厂商 ID 和模型 ID；自定义模式保存 Base URL 和用户输入的模型 ID，API 格式由应用内部固定为 OpenAI Chat Completions。

## 模型目录

第一版桌面端内置以下厂商：

- OpenAI
- DeepSeek
- 通义千问
- 智谱 GLM
- 月之暗面 Kimi
- 字节豆包

每个厂商包含稳定厂商 ID、展示名称、内部官方 Base URL、推荐模型 ID 和模型列表。每个模型包含稳定模型 ID、展示名称和可选说明。官方 Base URL 只在 Main 使用，不通过服务商选择界面展示。

模型目录采用“Java 后台优先、桌面端内置兜底”：

- 设置页打开时通过只读 IPC 向 Main 请求模型目录；
- Main 调用 Java 后台模型目录接口；
- 后台返回有效目录时使用后台结果；
- 后台不可用、超时或返回无效数据时返回桌面端内置目录；
- Renderer 不直接访问 Java 后台，也不维护远程目录缓存。

后台接口路径和响应结构在实现阶段沿用现有 Main 到 Java 后台的请求模式；目录响应必须在 Main 验证后才能返回 Renderer。

## 进程边界

新增只读模型目录业务能力，完整贯通 Main handler、Preload allowlist、Window 类型、共享请求响应类型、测试和 Electron IPC 契约。

现有单配置能力需要扩展为模型配置注册表，并区分服务商配置和自定义配置。服务商配置由 Main 根据厂商 ID 解析官方 Base URL；Renderer 不提交可修改的服务商 Base URL。自定义配置显式提交 Base URL、模型 ID 和 API Key，并由 Main 固定按 OpenAI Chat Completions 协议调用。列表和编辑状态永远不返回 API Key。工作流配置后续通过模型配置 ID 显式选择，不依赖默认模型。

模型目录本身不包含密钥。模型配置注册表和 API Key 本次仍只保存在 Main 内存中，不写入磁盘、Renderer 持久化或状态文本；应用重启后的安全持久化不在本次范围内。

## 状态与错误处理

- 目录读取期间禁用服务商模式中的厂商、模型、API Key 和添加按钮；自定义配置不依赖目录，可继续填写；
- 使用内置兜底目录时页面仍可配置，并以非阻塞提示说明当前使用内置目录；
- 目录为空或 Preload 能力不完整时显示接口不可用，并禁用保存；
- 已保存的厂商或模型不再存在时，回退到目录中的首个厂商及其推荐模型；
- 保存失败时显示 Main 返回的错误信息，保留用户当前选择和输入。

## 测试

覆盖以下行为：

- Main 后台目录成功与内置目录兜底；
- Main 对无效后台目录的验证；
- Preload 和共享类型的只读目录契约；
- Renderer 目录加载与加载禁用状态；
- 厂商切换只联动模型列表和推荐模型，界面不出现 Base URL；
- 自定义配置只显示 Base URL、模型 ID 和 API Key；
- 服务商保存提交厂商 ID、模型 ID 和 API Key；
- 自定义保存提交 Base URL、模型 ID 和 API Key；
- 模型列表不显示启停开关；
- 编辑模型时不回填 API Key，留空表示保留原密钥；
- 删除模型后列表移除对应配置；
- 列表不显示默认列，Main 注册表也不维护默认模型；
- API Key 不回填且保存成功后清空；
- 旧版或不完整 Preload API 的防御。
