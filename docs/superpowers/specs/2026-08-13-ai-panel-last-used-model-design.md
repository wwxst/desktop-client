# AI 对话框默认与上次使用模型设计

> 状态：已批准设计
> 适用范围：AI 对话框模型选择
> 日期：2026-08-13

## 背景

AI 对话框通过 `window.api.listAgentModelConfigurations` 加载模型页维护的模型配置。当前列表加载完成后，如果组件内没有仍然有效的选择，模型下拉框会保持空值。即使模型页只有一个模型，用户仍需手动选择；再次打开应用时也不会恢复上次选择。

## 目标行为

- 没有历史选择时，AI 对话框默认选择模型列表中的第一项。模型页只有一个模型时，即自动选择该模型。
- 用户在 AI 对话框的模型下拉框中选择模型时，立即记录该配置 ID，不以消息发送成功为前提。
- 后续重新挂载 AI 对话框或重新启动应用时，优先恢复仍然存在的上次选择。
- 如果上次选择的模型已经被删除，则回退到当前模型列表第一项，并记录新的回退选择。
- 如果当前没有可用模型，则保持未选择状态并清除失效记录。

## 方案

在 Renderer 使用 `localStorage` 保存最后选择的模型配置 ID。该偏好只影响 AI 对话框的展示和请求参数，不包含 API Key 等敏感信息，因此不需要扩展 Main、Preload 或 IPC 边界。

模型配置加载成功后，按以下顺序解析选择：

1. 当前组件选择仍存在时保留当前选择。
2. 否则，已记录的配置 ID 仍存在时选择该配置。
3. 否则，选择模型列表第一项。
4. 列表为空时使用空值。

解析出的非空选择与本地记录不一致时，更新本地记录；解析为空时删除本地记录。`localStorage` 读写使用异常保护，存储不可用时仍按当前模型列表完成本次默认选择，不阻断模型加载、模型切换或 AI 对话。

## 数据边界

- 持久化内容仅为模型配置 ID。
- 模型配置列表仍以 Main 返回结果为事实来源。
- 不在模型配置实体中增加“默认”或“启用”字段。
- 不改变设置页、模型目录、聊天 IPC 或模型配置持久化格式。
- 不改变 AI 对话框布局和文案。

## 刷新与删除

设置页新增、编辑或删除模型后，现有 `modelRefreshKey` 会触发 AI 对话框重新加载列表。重新加载时沿用上述解析顺序：有效当前选择保持不变；失效选择回退到上次有效记录或第一项。模型 ID 的编辑不影响选择，因为持久化使用稳定的配置 ID。

## 测试

在 `tests/ai-panel.test.tsx` 增加用户可观察行为测试：

- 无历史记录且只有一个模型时，该模型自动选中。
- 有多个模型时，重新挂载后恢复用户上次在下拉框中选择的模型。
- 本地记录指向已删除模型时，回退到列表第一项并更新记录。
- 模型列表为空时清除失效记录并保持未选择状态。
