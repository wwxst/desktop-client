# 智剪草稿导航设计

## 目标

把现有视频编辑器从登录后的默认内容中移出，放到开发环境专用的“智剪”菜单下，并在进入编辑器前增加一个草稿页。

登录后的整体三栏结构保持不变：左侧菜单栏、中间内容区、右侧 AI 区仍由现有 `Layout` 管理。此次只切换中间内容区，不修改左侧菜单栏和右侧 AI 区的默认宽度、拖动规则或现有外观，也不修改播放器、时间线、功能区和参数区。

## 页面流程

```text
登录成功
  -> 默认选中“首页”
  -> 中间显示空白页面

点击“小说推文”
  -> 中间显示空白页面

开发环境点击“智剪”
  -> 中间显示草稿页
  -> 点击“新建草稿”
  -> 中间显示现有视频编辑器
  -> 点击“返回草稿”
  -> 卸载编辑器并回到草稿页
```

正式环境不渲染“智剪”菜单，也不能通过中间内容状态显示智剪草稿页或编辑器。

## 已确认行为

- 登录成功后默认选中“首页”，不再直接显示视频编辑器。
- “首页”和“小说推文”本阶段只显示空白的中间内容区域，不增加标题、说明、卡片或待开发提示。
- “智剪”只在 `import.meta.env.DEV` 为真时显示；正式构建中完全隐藏。
- 第一次点击“智剪”进入草稿页，不直接进入编辑器。
- 草稿页本阶段只提供一个“新建草稿”入口，不显示虚构的草稿数据。
- 点击“新建草稿”后才创建并显示现有 `WorkspaceView`。
- 智剪编辑器提供“返回草稿”按钮，该按钮位于编辑器外层，不侵入播放器、时间线、功能区或参数区内部。
- 从编辑器返回草稿页，或在编辑器中切换到其他一级菜单时，当前临时编辑内容全部清空。
- 再次进入智剪时从草稿页开始；再次点击“新建草稿”创建一份全新的临时编辑状态。
- 已经位于智剪编辑器时，再次点击当前“智剪”菜单不触发返回或清空；用户通过“返回草稿”按钮明确退出编辑器。
- 登录后的左侧菜单栏和右侧 AI 区始终保留，只替换中间内容。

## 状态与组件职责

### `App`

`App` 继续管理登录页和登录后工作台的切换，并新增两组轻量页面状态：

- 当前一级菜单：`home`、`novel-promotion` 或 `smart-edit`。
- 智剪内部页面：`draft-list` 或 `editor`。

登录成功时将一级菜单初始化为 `home`，智剪内部页面初始化为 `draft-list`。`App` 根据这两个状态决定传给 `Layout` 的 `content`，但仍固定传入同一个左侧 `Sidebar` 和右侧 `AiPanel`。

一级菜单切换由 `App` 统一处理：

- 切换到“首页”或“小说推文”时，将智剪内部页面重置为 `draft-list`。
- 从其他菜单进入“智剪”时显示草稿页。
- 点击“新建草稿”时将智剪内部页面切换为 `editor`。
- 点击“返回草稿”时将智剪内部页面切换回 `draft-list`。

不引入路由库，也不把这些临时页面状态写入地址栏、本地存储或数据库。

### `Sidebar`

`Sidebar` 从自行保存选中菜单改为受控组件，接收当前菜单和菜单切换回调。这样菜单高亮与中间内容始终由同一份状态驱动，不会出现左侧显示“首页”、中间却显示编辑器的情况。

菜单顺序为：

1. 首页
2. 小说推文
3. 智剪，仅开发环境

原有头像、昵称、套餐信息和右侧设置图标保持不变。

### 空白页面

“首页”和“小说推文”共用一个无可见内容的中间区域容器。容器负责占满现有内容区域，但不渲染提示文字或装饰，避免现在加入以后会被推翻的临时界面。

### 智剪草稿页

草稿页是中间区域中的独立组件，只包含“新建草稿”入口。点击入口后通过回调通知 `App` 进入编辑器。

本阶段没有草稿列表数据，因此不实现草稿卡片、最近编辑时间、重命名、删除、搜索或分页。

### 智剪编辑器包装层

编辑器包装层只负责两件事：提供“返回草稿”按钮，并渲染现有 `WorkspaceView`。按钮不放进 `WorkspaceView`，从而保持现有编辑器内部布局和功能边界不变。

进入编辑器时才挂载 `WorkspaceView`；返回草稿页或切换其他菜单时立即卸载。现有 `WorkspaceView` 的 reducer 状态会随卸载销毁，已创建的媒体预览地址也由其现有清理逻辑释放，因此临时草稿不会残留到下一次进入。

## 开发与正式环境

开发环境中，`Sidebar` 显示“智剪”，`App` 允许渲染草稿页和编辑器。

正式环境中：

- `Sidebar` 不创建“智剪”菜单项。
- `App` 不应从任何正常交互进入 `smart-edit`。
- 内容选择逻辑增加防御性回退；如果状态异常地出现 `smart-edit`，仍显示首页空白内容，不显示未上线功能。

环境判断沿用项目现有的 `import.meta.env.DEV`，不新增功能开关系统。

## 临时草稿生命周期

本阶段的“草稿”只是一次编辑会话，不是持久化文件：

1. 用户点击“新建草稿”时挂载新的 `WorkspaceView`，由其创建新的初始编辑状态和首行草稿 ID。
2. 用户导入媒体、添加时间线片段或修改表单时，数据只存在于该组件内存中。
3. 用户点击“返回草稿”或切换到“首页”“小说推文”时，`WorkspaceView` 被卸载，临时状态随之清空。
4. 用户再次进入智剪并新建草稿时，得到全新的空白编辑器。

页面不弹出“是否保存”确认框，因为当前没有保存能力；退出即清空是本阶段已确认行为。

## 异常与防御性处理

- 菜单切换回调只接受已声明的菜单标识，避免显示未知内容页。
- 正式环境拒绝显示智剪内容，即使内部状态意外保留了 `smart-edit`。
- “新建草稿”和“返回草稿”只改变页面层状态，不复制或手动修改编辑器 reducer 数据。
- 快速切换菜单依靠 React 正常卸载组件；媒体地址继续由 `WorkspaceView` 的现有卸载清理负责，避免重复维护资源生命周期。
- 当前菜单与中间内容共用 `App` 状态，菜单高亮不会独立漂移。

## 本阶段不实现

- 不保存、恢复、重命名或删除真实草稿。
- 不接入数据库、本地文件、`localStorage` 或 Electron 持久化接口。
- 不实现草稿缩略图、草稿列表、自动保存、退出确认或崩溃恢复。
- 不引入 React Router 或其他路由库。
- 不修改登录认证流程，只改变登录成功后的默认中间内容。
- 不修改 `Layout` 的三栏尺寸、拖动行为和结构。
- 不修改 `AiPanel`、用户信息区、设置按钮、播放器、时间线、功能区和参数区。
- 不把“智剪”暴露到正式环境。

## 测试与验收标准

### 自动化测试

- 验证 `Sidebar` 由外部状态控制选中项，点击菜单会调用切换回调。
- 验证开发环境菜单顺序为“首页”“小说推文”“智剪”。
- 验证正式环境不包含“智剪”菜单项，也不渲染智剪内容。
- 验证登录后默认中间内容为首页空白页，而不是 `WorkspaceView`。
- 验证“首页”和“小说推文”不渲染可见占位内容。
- 验证点击“智剪”先显示草稿页，点击“新建草稿”后才挂载 `WorkspaceView`。
- 验证点击“返回草稿”会卸载 `WorkspaceView` 并恢复草稿页。
- 验证从编辑器切换到其他菜单后，再次进入智剪只显示草稿页，不保留临时编辑器。
- 保留并运行现有播放器、时间线、媒体导入和三栏布局测试，防止既有功能回归。

### 人工验收

- 开发环境登录后，“首页”高亮，中间为空白，左右两栏正常显示。
- “小说推文”高亮时，中间仍为空白，左右两栏不重新布局。
- 点击“智剪”只看到草稿页和“新建草稿”入口。
- 新建后能使用当前完整编辑器，播放器、时间线、功能区和参数区外观与行为保持不变。
- 导入媒体并修改编辑内容后返回草稿，再次新建时编辑器恢复全新空白状态。
- 正式构建中左侧没有“智剪”，首页和小说推文均无法进入编辑器。
- 执行完整测试、lint、类型检查、生产构建和 `git diff --check`。
