# TTS 音色卡片试听设计

## 目标

在现有 TTS 配音页中，将试听入口从右侧面板底部移动到每个音色卡片内。用户点击某个音色的“试听音色”后，客户端生成试听音频并立即播放，不再展示额外的音频播放器。

本次只调整试听入口和播放交互，保留现有动态音色目录、语言选择、搜索、性别筛选、音色描述、SID、高级设置和正式生成功能。

## 交互规则

- 每个音色卡片包含独立的“试听音色”按钮。
- 点击试听不会改变当前单选音色；单选框只决定正式生成所用的音色。
- 试听生成期间，当前卡片显示“生成中”，并禁用其他试听按钮，避免多个本地推理任务并发。
- 试听生成成功后立即自动播放，不显示可见的音频播放器。
- 播放期间，当前卡片显示“播放中”。
- 点击其他音色的试听按钮时，先停止当前音频，再生成并播放新的音色。
- 同一试听条件下再次点击同一音色时，复用已生成音频并从头播放，不重复调用 TTS。
- 文案、文本语言、语速或音色任一变化后，不复用旧试听结果。
- 正式配音任务运行期间，试听按钮继续沿用现有禁用规则。

## 页面布局

音色卡片由两个独立区域组成：

1. 选择区域：单选框、现有音色头像、名称、描述和 SID。
2. 操作区域：“试听音色”按钮及其生成、播放状态。

卡片容器不使用 `label` 包裹按钮，避免交互控件嵌套。选择区域使用独立 `label` 关联单选框，试听按钮只触发试听。

右侧面板底部移除全局“试听”按钮和试听播放器，只保留“高级设置”和“开始生成”。两个按钮始终位于同一行：“高级设置”为固定紧凑宽度，“开始生成”占据剩余宽度；窄面板下也不改为上下排列。

## 状态与数据流

渲染层维护以下试听状态：

- 正在生成的音色 ID。
- 正在播放的音色 ID。
- 当前音频对象或元素引用。
- 当前试听音频的对象 URL。
- 当前试听签名，由音色 ID、模型 ID、试听文本、文本语言和语速组成。

点击试听时：

1. 根据点击的音色构建请求，不读取或修改正式生成所用的选中音色。
2. 停止当前播放并将播放位置重置。
3. 若试听签名与缓存一致，直接从头播放缓存音频。
4. 否则调用现有 `window.api.previewTts`。
5. 将返回的 WAV 字节转换为对象 URL，并立即调用音频播放。
6. 新音频替换旧音频时释放旧对象 URL；组件卸载时停止播放并释放资源。

主进程、preload、IPC 和 TTS 引擎接口保持不变。

## 错误处理

- TTS 生成失败时，恢复按钮状态并沿用页面现有错误通知。
- 浏览器拒绝或无法开始播放时，显示明确的“试听播放失败”通知，不展示备用播放器。
- 试听请求未完成时不允许发起第二个请求，避免结果乱序和本地 CPU 并发占用。
- 音频播放结束或发生错误后，清除“播放中”状态。
- 组件卸载后不再更新试听状态。

## 测试范围

组件测试覆盖：

- 每个动态音色卡片都显示“试听音色”。
- 点击试听使用该卡片自身的 `modelId` 和 `voiceId`，且不会改变已选中的单选音色。
- 返回音频后自动调用播放，不渲染可见的 `audio` 控件。
- 当前卡片在请求期间显示“生成中”，其他试听按钮被禁用。
- 相同试听签名复用缓存并从头播放。
- 文案、语言或语速变化后重新生成试听。
- 切换音色会停止当前播放并播放新结果。
- 生成失败和播放失败时恢复状态并显示错误。
- 底部只保留同一行的“高级设置”和“开始生成”。

验证继续运行现有 TTS 试听样本文本测试、音色选择测试、工作区测试，并执行 lint、类型检查和完整测试。

## 非目标

- 不增加固定真人头像或为动态音色硬编码头像映射。
- 不增加每个音色的转换字数配额字段。
- 不修改正式生成、保存 WAV、插件安装或音色目录逻辑。
- 不增加暂停、进度条、音量或其他试听播放器控件。
