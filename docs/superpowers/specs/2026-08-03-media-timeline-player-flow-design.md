# 媒体、时间线与播放器联动设计

## 目标

在不改动外侧菜单栏、AI 对话栏、工作区三栏布局和现有草稿表单外观的前提下，打通第一条真实编辑链路：

```text
媒体区导入视频 -> 点击“添加” -> 生成时间线片段 -> 自动选中片段 -> 播放器停在第一帧
```

“导入”只把文件放入媒体库；“添加”才表示把素材加入时间线。播放器不直接接收媒体区的临时点击状态，而是始终预览当前选中的时间线片段。

## 界面行为

### 媒体区

- 保留现有导入按钮、媒体卡片、缩略预览、时长和“添加”按钮。
- 导入成功后，素材只出现在媒体区，不改变播放器和时间线。
- 点击“添加”后，素材按点击顺序追加到下方时间线素材轨道。
- 同一素材本阶段只能添加一次；已进入时间线后按钮显示“已添加”并禁用，避免重复片段。
- 无法读取的视频显示现有错误占位，并禁止添加到时间线。

### 时间线

- `Timeline` 仍位于工作区下半部分，并继续横跨功能区、播放器和参数区。
- 在现有“草稿名 / 固定开头 / 音频 / 固定结尾”四列表单上方增加一条紧凑的横向素材轨道。
- 每个时间线片段显示视频名称和时长；片段宽度本阶段保持稳定，不按真实时长缩放。
- 新添加的片段自动成为当前片段，并使用清晰但克制的选中态。
- 点击其他片段可以切换当前片段，播放器随之切换并回到该片段第一帧。
- 现有四列表单、行新增、行删除、上传选框和无竖分割线样式保持不变。

### 播放器

- 没有时间线片段时继续显示现有空白画布和禁用的播放控制。
- 有当前片段时，在当前画布比例内显示真实 `<video>`，视频使用 `contain` 适配，画布仍默认 `9:16` 并保持居中。
- 新增或切换片段时暂停视频，并定位到 `0` 秒；加载完成后显示第一帧，不自动播放。
- 播放按钮在视频可播放后启用，并在播放/暂停之间真实切换。
- 左侧时间显示跟随当前播放时间和视频总时长更新。
- 本阶段不实现拖动播放头、裁剪、变速、音量、全屏和多轨同步。

## 状态架构

`WorkspaceView` 是编辑工作区共享数据的唯一拥有者。使用 React `useReducer` 管理项目状态，不引入 Redux 或 Zustand。

共享状态包含：

- `assets`：已导入的媒体素材，包括稳定 ID、文件名、预览 URL、时长和可用状态。
- `clips`：已加入时间线的片段，包括稳定 ID 和对应的素材 ID。
- `activeClipId`：当前由时间线选中的片段。
- `aspectRatio`：当前画布比例，默认 `9:16`。
- `draftRows`：现有草稿表单行。

组件职责：

- `WorkspaceView` 创建编辑状态，派发动作，并把数据与回调传给三个子区域。
- `FunctionPanel` 保留分类滚动、文件输入和媒体卡片预览等局部交互；导入和添加通过回调更新共享状态。
- `Timeline` 渲染共享的时间线片段和草稿表单行；片段选择、表单修改、增行和删行通过回调更新共享状态。
- `PlayerPanel` 接收当前素材与画布比例；比例弹窗开关、自定义输入和 `<video>` 播放状态仍为局部 UI 状态。

媒体素材、时间线片段和草稿表单不再分别由三个叶子组件各自保存，避免“媒体区显示已添加，但时间线和播放器不知道”的状态断裂。

## 数据流

1. 用户选择文件，`FunctionPanel` 为每个文件创建浏览器预览 URL，并上报导入动作。
2. 元数据加载后，素材时长和可用状态写回共享资产。
3. 用户点击“添加”，reducer 为该资产创建一个时间线片段，将其追加到 `clips`，并更新 `activeClipId`。
4. `Timeline` 根据 `clips` 渲染片段；`PlayerPanel` 通过 `activeClipId -> clip -> asset` 获得唯一当前视频。
5. 用户选择另一个片段时，只更新 `activeClipId`；播放器暂停、归零并加载对应素材。
6. 工作区卸载时统一释放所有 `blob:` URL，避免媒体区局部卸载导致播放器中的 URL 提前失效。

## 异常处理

- 空文件选择不产生状态变化。
- 重复“添加”不创建重复片段。
- 元数据或视频帧加载失败时，素材标记为不可用，媒体卡片保持错误提示，播放器不进入可播放状态。
- 播放器切换素材时先暂停旧视频；异步媒体事件只更新当前 `<video>` 的显示状态，避免旧素材事件污染新素材。
- 本地 `blob:` 视频继续使用已修复的 CSP `media-src 'self' blob:` 策略，不扩大脚本权限。

## 本阶段不做

- 不修改 `Sidebar`、外层 `Layout`、AI 对话栏、主进程或 preload。
- 不做 Electron 安全边界重构；该工作独立安排，避免和播放器联动混在一次改动中。
- 不保存或恢复工程，不保存本地绝对路径。
- 不做真正的多轨剪辑、片段排序、删除、裁剪、拖拽播放头、导出或 FFmpeg 处理。
- 不改变现有参数区空白状态。

## 验证

- 为纯 reducer 添加行为测试，覆盖导入素材、拒绝重复片段、按顺序追加片段、自动选中和切换选中片段。
- 更新工作区契约测试，确认数据通过 `WorkspaceView` 在媒体区、时间线和播放器之间传递，并保留现有布局与表单结构。
- 使用真实 MP4 验证：导入后播放器不变化；点击“添加”后时间线出现片段；播放器显示第一帧；播放按钮可播放和暂停；切换片段会暂停并回到第一帧。
- 运行完整测试、lint、类型检查、生产构建和 `git diff --check`。
