# desktop-client 视频编辑器
# 交互与界面完整重构计划

> 项目：`https://github.com/wwxst/desktop-client`
>
> 目标：把当前“有播放器 + 有时间线”的编辑页面，升级成真正具有剪映 / OpenCut 操作手感的视频编辑器。
>
> 本阶段不追求堆功能数量，优先解决：**拖、放、选、移、裁、缩、右键、快捷键、画布操作、时间线导航、视觉层级**。
>
> 核心原则：
>
> **用户负责“我想把这个东西放哪、怎么剪”；软件负责“它属于哪一层、怎么管理轨道、怎么执行命令”。**

---

# 1. 为什么现在必须先做这一轮

当前编辑器底层已经有：

- Editor Project
- Clip
- Track
- Command
- Undo / Redo
- Timeline
- Composition Preview
- Agent API

但实际使用体验还存在明显差距：

- 素材不能像剪映一样直接拖入时间线
- 时间线 Clip 拖动手感弱
- 时间线不能自然平移
- 预览画布里的视频不能直接拖动、缩放
- 轨道概念过于显眼，像“表格”
- 大量横纵网格导致界面像排期系统
- Clip 缺少缩略图，时间线辨识度低
- 右键菜单体系不完整
- 多选、框选、吸附、快捷键等基础编辑交互不足
- 用户需要理解程序的轨道结构，而不是直接剪视频

因此：

> **这一阶段暂停继续堆字幕、TTS、复杂导出、特效等新功能。**

先把编辑器的基础 UX 做到“真的能顺手剪”。

---

# 2. 最终用户应该感受到什么

用户不应该看到或思考：

```text
这是第几视频轨？
这是 Overlay 轨吗？
这里能不能放视频？
我要不要新建一条轨？
```

用户应该只需要：

```text
把视频拖进来
↓
想放主视频就放主视频
↓
想叠在上面就往上拖
↓
想再叠一层就继续往上拖
↓
拖音频到下面
↓
软件自动出现新的音频层
```

即：

> **弱化“轨道管理”，强化“直接摆放内容”。**

---

# 3. 时间线最终视觉方向

## 当前需要避免

类似：

```text
V2 ─┼─┼─┼─┼─┼─┼─┼─┼
V1 ─┼─┼─┼─┼─┼─┼─┼─┼
A1 ─┼─┼─┼─┼─┼─┼─┼─┼
```

问题：

- 像 Excel
- 空白区域过多
- 用户第一眼关注“格子”，而不是视频
- 轨道编号抢视觉
- Clip 不够突出

---

## 改成内容型时间线

目标视觉：

```text
          00:00       00:05       00:10       00:15
            │            │            │            │

             [字幕：这是第一句话──────────]

        [LOGO]        [贴纸]

             [补充视频────────]

[主视频A ▣ ▣ ▣ ▣ ▣][主视频B ▣ ▣ ▣ ▣ ▣ ▣]

[小说配音 ▂▅██▅▂▁▃████▆▂▁████████████]

        [BGM ▂▃▆████▅▂▁▃▅████████████]
```

重点：

- 不显示 V1 / V2 / A1
- 不铺满完整纵向网格
- 保留非常淡的时间辅助线
- 时间尺是主要定位依据
- 内容块是视觉中心
- 视频显示缩略图
- 音频显示波形
- 文字直接显示文字摘要
- 选中内容有明确边框
- 拖动内容有 Ghost Preview

# 4. 轨道系统重新定义

## 用户层面

尽量不出现“轨道”术语。

用户看到的是：

- 主视频
- 上面的叠加内容
- 下面的声音内容

甚至“主视频”文字也可以仅在 Hover / 空项目引导时出现。

---

## 程序内部

程序仍然可以有：

```text
视觉层
声音层
主视觉层
```

但这些是内部模型，不是用户操作限制。

---

## 视觉内容自由摆放

以下内容以后都属于“画面内容”：

- 视频
- 图片
- 文字
- 字幕
- Logo
- 贴纸
- 图形
- 特效元素

这些内容可以：

```text
自由上下移动
自由叠放
自由创建新层
```

---

## 声音内容

以下属于声音区域：

- 配音
- BGM
- 音效
- 单独音频

拖到声音区域即可。

不要求：

```text
先创建音频轨
↓
再添加
```

而是：

```text
用户拖到下面
↓
自动出现一层
```

# 5. 动态创建层

这是本轮重点。

例如已有：

```text
       [补充视频]
[主视频────────────]

[配音──────────────]
```

用户再拖一个视频到最上方：

```text
        ↓
        ↓
       鼠标
```

时间线显示：

```text
┄┄┄┄┄┄┄ + 放在新的一层 ┄┄┄┄┄┄┄

       [补充视频]

[主视频────────────]
```

松手后：

```text
[新视频──────]

       [补充视频]

[主视频────────────]
```

程序自动创建内部 Layer。

音频同理：

```text
[配音────────]

拖 BGM 到下面
↓

[配音────────]

[BGM─────────]
```

# 6. 空层清理

用户删除某一整层全部内容后：

如果该层：

- 没有 Clip
- 没有锁定
- 不是主视频基础层

则可以自动消失。

避免：

```text
空轨
空轨
空轨
空轨
主视频
空轨
空轨
```

越剪越乱。

# 9. Clip 选择状态

必须明确三种视觉状态：

## 普通

没有强边框。

## Hover

- 显示裁剪手柄

## Selected

# 10. Clip 拖动

## 基础行为

按住 Clip：

```text
鼠标移动多少
↓
Clip 就跟多少
```

不能：

```text
鼠标已经走了
Clip 半天不动
```

---

## 拖动过程中

必须展示：

### Ghost Preview

原位置降低透明度：

```text
░░░░░░░░
```

移动位置显示：

```text
████ 视频 ████
```

---

### 当前放置层高亮

鼠标经过哪一层：

该区域轻微高亮。

---

### 新层提示

拖到现有视觉内容上方：

```text
+ 放到新的一层
```

---

### 禁止区域

比如把纯音频拖到画面区域：

显示禁止 Cursor。

但不要弹出烦人的错误框。

---

# 11. 拖动边缘自动滚动

如果用户拿着 Clip 拖到时间线最右边：

不能停住。

应：

```text
靠近右边缘
↓
时间线自动向右滚
↓
继续拖
```

左边同理。

速度可以根据距离边缘决定：

```text
距离越近
滚动越快
```

---

# 12. 时间线平移

不能逼用户抓底部横向滚动条。

至少支持：

## 中键拖动

```text
鼠标中键按住
↓
左右拖
↓
时间线平移
```

## Shift + 滚轮

横向滚动。

## 空格 + 左键拖动

可考虑与画布统一：

```text
Space + Drag = Pan
```

最终快捷键方案需避免与“Space 播放/暂停”冲突：

```text
点击 Space = 播放/暂停
按住 Space + Drag = 临时抓手
```

# 13. 时间线缩放

支持：

```text
Ctrl + 鼠标滚轮
```

重点：

> **以鼠标当前位置为缩放中心。**

不是永远围绕时间线最左边放大。

例如鼠标在 35 秒：

```text
35 秒
  ↑
鼠标
```

放大以后：

35 秒仍尽量保持在鼠标下面。

这是影响剪辑手感的重要细节。

# 17. 基础吸附 Snapping

这一项从后续版本提前到本阶段。

原因：

没有吸附，Clip 拖动永远感觉“飘”。

第一版吸附对象：

```text

Clip 结尾
播放头
工程 0 秒
```

以后再增加：

```text
Marker
字幕边缘
Beat
关键帧
```

# 18. 主视频磁吸

这一项可以做基础版，但与普通吸附分开。

主视频区域中：

```text
[视频A][视频B][视频C]
```

如果删除 B：

基础“磁吸模式”可以：

```text
[视频A][视频C]
```

如果关闭磁吸：

```text
[视频A]       [视频C]
```

本阶段先预留 Toolbar 开关。

真正复杂 Ripple 行为可以下一阶段继续完善。

# 19. Trim 裁剪

鼠标靠近 Clip 左右边缘：

Cursor 自动变化。

例如：

```text
←│ 视频 │→
```

拖左边：

改素材入点。

拖右边：

改素材出点。

---

## Trim 手感要求

- 拖动实时预览
- 不超过素材真实长度
- 不越过 0 秒
- 最小时长保护
- 吸附生效
- Shift 可临时关闭吸附
- 一次完整拖动只产生一个 Undo History

# 69. 【新增】视频原声必须作为正式能力保留

这一项不是后续功能，而是当前基础编辑器必须修复的问题。

当前工程预览逻辑中，视频画面存在，但视频自己的声音可能被强制静音。

正确行为：

```text
视频素材拖入时间线
↓
默认：
画面正常
原声正常
```

用户可以单独控制：

- 视频 Clip 音量
- 视频 Clip 静音
- 所在层整体静音
- 后续音画分离

逻辑：

```text
视频本身 muted = true
→ 不播放原声

所在声音控制被静音
→ 不播放原声

否则
→ 按 Clip volume 正常播放原声
```

要求：

- [ ] 视频默认有原声
- [ ] 右侧音量参数对视频原声生效
- [ ] Clip 静音生效
- [ ] Undo / Redo 生效
- [ ] 工程预览和最终导出行为一致

# 91. 【新增】事务模型建议

增加：

```ts
editor.transaction('drag-asset-to-new-layer', () => {
  createLayer()
  addClip()
  selectClip()
})
```

History 中只记录一个 Entry。

未来 Agent：

```text

```

也可以：

```text
一个 Agent Action
=
一个 Transaction
```

用户：

```text

```

一次撤销。

# 92. 【新增】Batch Command 与 Transaction 区别

`executeBatch()`：

表示一次执行多个命令。

`transaction()`：

表示：

> 这些命令在 History 和失败回滚上属于一个整体。

以后 Agent 应优先使用：

```text
Transaction
```

而不是简单调用 20 次 execute。

# 116. 【更新】新的最高优先级

现在最高优先级不再只是：

```text
“把 Drag 做出来”
```

而是：

```text
交互不冲突
+
拖动跟手
+
自动管理层
+
时间线视觉不像表格
+
画布直接可编辑
+
右键/快捷键完整
+
所有操作可撤销
```

---

# 117. 【最终补充后的核心原则】

最终整个编辑器要满足：

> 用户不需要理解“轨道编号”。

> 用户不需要手动创建轨道。

> 用户不需要为了移动一个视频去填写数字。

> 用户不需要靠底部滚动条才能移动时间线。

> 用户不需要进入右侧面板才能改变画面位置。

> 用户做错任何一个普通操作都能立刻 Undo。

> 同一个动作从鼠标、右键、快捷键、Toolbar、Agent 发起，最终走同一个 Editor Core。

> 界面不能依赖大量网格和边框来证明“这里是一个编辑器”。

> 内容、播放头、选择状态、吸附线才应该是时间线最明显的视觉元素。

---

# 118. 补充后的最终一句话

> **这一轮不是“优化一下编辑器 UI”，而是把现有编辑器真正补齐成一套成熟的桌面 NLE 基础交互系统：用户像用剪映一样自然操作，而我们的底层仍然保持为模板、Workflow 和 Agent 服务。**
